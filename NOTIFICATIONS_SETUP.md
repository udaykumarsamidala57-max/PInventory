# Android workflow notifications

The Android app uses Firebase Cloud Messaging for device push and keeps a per-user inbox in the `inventory` authentication database. The API only registers the authenticated session's FCM token; it never accepts a user ID from the phone. Device tokens are removed on logout.

## Workflow events

| Event | Recipients |
| --- | --- |
| Indent submitted | Department in-charges for the selected store (and applicable Global/Admin approvers) |
| Indent level 1 / final approved or rejected | Indenter; after level 1 approval the final Global approvers are alerted; after final Issue approval Store users are alerted |
| Purchase order created | Every Global/Global12 user assigned to that store |
| Purchase order approved | Finance department users assigned to that store |
| New complaint | Store maintenance admins |
| Service request assignment, status change or follow-up | Requester, assigned in-charge and admins; actor is not redundantly notified |
| Stock issued | User who raised the indent |
| New School Operations visitor request | The PInventory account selected as the visitor's host; the alert includes Approve and Reject actions |

These notifications are generated by Android API actions and the corresponding web workflows, so approvals, service updates and issue activity performed on either client are reflected in the same Android inbox. School Operations sends signed visitor events to the PInventory mobile API; mobile decisions are signed back to School Operations, which verifies the logged-in PInventory user is the visitor's selected host. Push delivery is asynchronous; if FCM is temporarily unavailable, the inbox row remains saved.

## Deployment setup

1. Apply `src/main/resources/sql/mobile_notifications.sql` to the `inventory` authentication database once. It creates the device-token registry and notification inbox tables.
2. For local Tomcat, the Windows user settings file already points `FIREBASE_SERVICE_ACCOUNT_FILE` at the private key stored under `%LOCALAPPDATA%\PInventory`. Keep that key outside Git and restrict access to the service account that runs Tomcat.
3. For a hosted server, set `FIREBASE_PROJECT_ID=office-central-erp` and `FIREBASE_SERVICE_ACCOUNT_JSON` to the service-account JSON as a protected host secret. Do not add the JSON key to the repository or Android package.
4. Set the same `SCHOOL_OPERATIONS_SSO_SECRET` in PInventory and School Operations. Configure `SCHOOL_OPERATIONS_BASE_URL` in PInventory and `PINVENTORY_BASE_URL` in School Operations so both services can reach each other over HTTPS. Local defaults are PInventory at `http://localhost:8080/` and School Operations at `http://localhost:8083/`.
5. Build and install the Android APK. FCM tokens are associated with a PInventory user after Android login and removed on logout, so visitor alerts go only to that account's signed-in device tokens. On Android 13 and later, users must allow notification permission. The Firebase Android app is registered as `com.pinventory` in `office-central-erp` and `app/google-services.json` is its generated client configuration.

`FIREBASE_SERVICE_ACCOUNT_JSON` takes precedence over the local file path. If neither is configured, the backend uses Application Default Credentials.
